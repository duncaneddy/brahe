    Changelog¶

    All notable changes to this project will be documented in this file.

    The format is based on Keep a Changelog. Brahe's versioning and deprecation policy is modeled on NumPy's policy rather than strict SemVer — see the versioning documentation for the full policy, including the transitional deprecation window currently in effect.

    Each release groups entries under the Keep a Changelog section headings in the order Added, Changed, Deprecated, Removed, Fixed. Entries in Deprecated correspond to APIs that still work in this release but emit a DeprecationWarning or FutureWarning; entries in Removed list APIs that previous releases had deprecated.

    [1.8.0] - 2026-10-16¶

    Added¶

    • Crate-private utils::batch primitives (batch_map, batch_zip, batch_map_epochs, PARALLEL_THRESHOLD) with the length-1-or-N broadcast rule and shared-epoch context hoisting used by all vectorized transformation functions. @duncaneddy (#436)
    • Batch Earth frame transformations rotations_/positions_/states_{eci_to_ecef,ecef_to_eci,gcrf_to_itrf,itrf_to_gcrf} and positions_/states_{gcrf_to_eme2000,eme2000_to_gcrf} in Rust; a shared epoch hoists the IAU 2006/2000A rotation matrices across the batch. @duncaneddy (#437)
    • Python rotation_/position_/state_* Earth frame functions accept batches of vectors with an axis keyword (default -1, numpy component-axis convention) and Epoch | Sequence[Epoch] epoch arguments; single-vector calls are unchanged. @duncaneddy (#437)
    • Learn page "Vectorized Transformations" and examples/frames/vectorized_transforms.{py,rs}. @duncaneddy (#437)
    • Batch lunar, Mars, EMB, IAU, synodic (EMR/SER/GSE), and generic frame-router transformations in Rust (rotations_/positions_/states_*, rotations_icrf_to_body_fixed_iau, rotations_/positions_/states_frame_to_frame). @duncaneddy (#438)
    • Python planetary, synodic, and router frame functions accept batches (axis keyword) and epoch sequences. @duncaneddy (#438)
    • Batch coordinate transformations in Rust: states_koe_to_eci/states_eci_to_koe (+ _for_body), positions_{geodetic,geocentric}_to_ecef and inverses, positions_/states_{radec_to_inertial,inertial_to_radec}, positions_{radec_to_azel,azel_to_radec}, rotations_ellipsoid_to_{enz,sez} and inverses, relative_positions_{ecef_to_enz,enz_to_ecef,ecef_to_sez,sez_to_ecef}, positions_{enz,sez}_to_azel, points_in_polygon. @duncaneddy (#439)
    • Python coordinate functions accept batches with the axis keyword; relative-position functions broadcast a single site across a batch of positions (and vice versa); position_radec_to_azel/position_azel_to_radec accept epoch sequences. @duncaneddy (#439)
    • Batch relative-motion transformations in Rust (rotations_/states_* for RTN, ROE, and Keplerian-pair conversions) with chief/deputy broadcasting. @duncaneddy (#440)
    • Python relative-motion functions accept batches with the axis keyword; a single chief or deputy broadcasts across the other argument's batch. @duncaneddy (#440)
    • Batch equinoctial conversions states_koe_to_equinoctial / states_equinoctial_to_koe in Rust and batched input in Python. @duncaneddy (#441)
    • Python Keplerian property and anomaly functions accept (n, 6) element-set batches and element-wise arrays with numpy broadcasting against e; semimajor_axis* functions accept arrays; orbital_period_from_state accepts batched states. @duncaneddy (#441)
    • set_vectorization_length_threshold(n) / get_vectorization_length_threshold() in Rust (brahe::utils) and Python to configure the batch length at which vectorized functions use the global thread pool (default 1024). @duncaneddy (#451)
    • Typed CCSDS ADM reference-frame vocabularies mirroring the SANA registries (CCSDSCelestialBodyFrame, CCSDSOrbitRelativeFrame, CCSDSSpacecraftBodyFrame, ADMReferenceFrame), bidirectional conversion bridges between those vocabularies and the native ReferenceFrame type, and the APMHeader/AEMHeader/TDMHeader message headers, as the foundations for CCSDS APM/AEM/TDM support. @duncaneddy (#453)
    • BRAHE_NETWORK_MODE environment variable (online, offline, offline-strict) gating every network request brahe makes and controlling whether cached files past their time-to-live are refreshed, served, or rejected; network_mode() in Rust and brahe.network_mode() in Python read the active mode. @duncaneddy (#454)
    • docs/learn/utilities/environment_variables.md reference page for every environment variable the library reads. @duncaneddy (#454)
    • Attitude kinematics functions quaternion_derivative, angular_velocity_from_quaternion_derivative, euler_rates_to_angular_velocity, and angular_velocity_to_euler_rates, grounded in Diebel (2006) and verified by finite differences against the existing attitude representations. The quaternion pair takes a scalar_first argument selecting the component layout of the raw quaternion derivative, matching Quaternion::from_vector and Quaternion::to_vector. @duncaneddy (#455)
    • scripts/warm_data_cache.py --only <family> / --refresh and the celestrak:group:<name> manifest form. @duncaneddy (#460)
    • CCSDS APM (Attitude Parameter Message, 504.0-B-2) support: typed message structs with quaternion, Euler-angle, angular-velocity, spin, inertia, and maneuver blocks; KVN, XML, and JSON reading and writing; and Python bindings. The APM XML writer rejects characters XML 1.0 forbids, matching the other XML writers. @duncaneddy (#464)
    • spd_sqrtm_dmatrix for the square root of a dynamically sized symmetric positive semi-definite matrix, computed by eigendecomposition. It symmetrizes its input, clamps eigenvalues that are negative only to within round-off rather than rejecting them, and reports a decomposition that fails to converge instead of returning NaN. @duncaneddy (#467)
    • CCSDS AEM (Attitude Ephemeris Message, 504.0-B-2) support: segmented attitude ephemerides with all nine attitude data types; KVN, XML, and JSON reading and writing; conversion to and from attitude trajectories; and Python bindings. @duncaneddy. @duncaneddy (#471)
    • AttitudeTrajectory, relating two ReferenceFrame endpoints, with slerp, linear, and Lagrange attitude interpolation and attitude kinematics-based normalization of AEM data on ingest. It implements OrientationProvider, so an attitude history can serve as a frame-graph orientation source. @duncaneddy. @duncaneddy (#471)
    • AEM::register_for(name) registers a single-segment AEM's attitude as the orientation of an object's body frame, binding the message's unbound body endpoint to the object and inverting the series when the celestial endpoint is REF_FRAME_B. @duncaneddy. @duncaneddy (#471)
    • The SPICE kernels the unit test suites load are included in the repository, so cargo test succeeds immediately after cloning without a separate data-download step. @duncaneddy (#496)
    • CelestialFrame::MOD and CelestialFrame::TOD in the reference frame router, including from_string/Display support and the corresponding CelestialFrame.MOD/CelestialFrame.TOD Python attributes. @duncaneddy (#526)
    • Equinox-based Earth frame transformations bias_precession_iau2000, nutation_iau2000b, gast_rotation_iau2000b, and the rotation_/position_/state_ functions with batch forms for GCRF/MOD, MOD/TOD, GCRF/TOD, and TOD/ITRF in both directions (Rust and Python). @duncaneddy (#526)
    • MOD and TOD frame choices in the brahe transform CLI commands. @duncaneddy (#526)
    • Learn page and API reference for the equinox-based frames with six standalone examples in Python and Rust. @duncaneddy (#526)
    • OrbitTrajectory.to_frame(frame) (Rust DOrbitTrajectory::to_frame / SOrbitTrajectory::to_frame) converting a trajectory to any ReferenceFrame through the reference frame router, including orbit-relative frames of registered objects. @duncaneddy (#527)
    • ReferenceFrame == CelestialFrame comparisons in Rust (PartialEq both directions) and Python (ReferenceFrame.__eq__ accepts a CelestialFrame). @duncaneddy (#527)
    • KeplerianPropagator and SGPPropagator accept any Earth-rooted ReferenceFrame as output frame (for example CelestialFrame.TOD or a bound RTN frame), and Keplerian output is accepted in EME2000 as well as GCRF. @duncaneddy (#527)
    • OPM.state_in_frame(frame) (Rust OPM::state_in_frame) converting the message state vector from its declared REF_FRAME to any CelestialFrame or ReferenceFrame through the reference frame router. @duncaneddy (#528)
    • TryFrom<&CCSDSRefFrame> for CelestialFrame (with TryFrom<&CCSDSRefFrame> for ReferenceFrame delegating to it) and TryFrom<&ReferenceFrame> for CCSDSRefFrame mapping EME2000/J2000, GCRF, the ITRF realizations, and TOD (the reverse direction writes ITRF as ITRF2000 and rejects MOD, which has no ODM token). @duncaneddy (#528)
    • ADM TOD_EARTH and MOD_EARTH reference-frame tokens map to CelestialFrame::TOD and CelestialFrame::MOD in both directions. @duncaneddy (#528)
    • PrecessionNutationModel (IAU2006A, IAU2000B) with set_precession_nutation_model / get_precession_nutation_model and bias_precession_nutation_model(epc, model) in Rust and Python. @duncaneddy (#532)
    • FrameAxes and FrameCenter types, CelestialFrame::Centered, CelestialFrame::centered(center, axes), CelestialFrame::axes(), and CelestialFrame::center() in Rust and Python (FrameAxes, FrameCenter, CelestialFrame.Centered(center, axes), .axes, .center, .center_naif_id). @duncaneddy (#536)
    • NAIFId::name(), NAIFId::from_name() (accepting NAIF aliases such as SSB and EMB), and Display for NAIFId; Python NAIFId.from_name() and NAIFId.naif_name. @duncaneddy (#536)
    • Python ReferenceFrame.celestial_frame returning the wrapped CelestialFrame (or None), so a trajectory's frame exposes axes and center. @duncaneddy (#536)
    • brahe::ccsds::interop::segment_celestial_frame, state_for_segment, and state_into_segment_axes for writing trajectories into OEM segments, shared by the Python bindings. @duncaneddy (#536)
    • CCSDSRefFrame::ICRF and CCSDSRefFrame::MCI tokens; TryFrom<&CCSDSRefFrame> for FrameAxes; brahe::ccsds::interop::odm_celestial_frame resolving a message's REF_FRAME, REF_FRAME_EPOCH, and center to a CelestialFrame; NAIFId implements FromStr. @duncaneddy (#536)
    • Example examples/frames/mars_centered_eme2000 and the "Axes and Centers" section of the frame transformations page. @duncaneddy (#536)
    • Keplerian element trajectories and propagator output in the MOD and TOD frames for OrbitTrajectory, KeplerianPropagator, and SGPPropagator, alongside the ICRF-aligned inertial frames and EME2000. @duncaneddy (#539)
    • FrameAxes::TEME and CelestialFrame::TEME in the reference frame router with from_string/Display support, the FrameAxes.TEME and CelestialFrame.TEME Python attributes, and the TEME choice in the brahe transform CLI commands. @duncaneddy (#542)
    • Keplerian element trajectories and propagator output in TEME axes for OrbitTrajectory, KeplerianPropagator, and SGPPropagator, alongside MOD and TOD. @duncaneddy (#542)
    • gmst82, greenwich_mean_sidereal_rotation, and the rotation_/position_/state_ functions with batch forms for GCRF/TEME and TEME/ITRF in both directions (Rust and Python). @duncaneddy (#542)
    • CCSDS mappings for the ODM TEME and ADM TEMEOFDATE reference frame tokens to CelestialFrame::TEME in both directions; OEM, OPM, and AEM messages in TEME convert to native trajectories and states. @duncaneddy (#542)
