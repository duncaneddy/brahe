IGS Precise Products¶

The International GNSS Service (IGS) and its analysis centers publish precise orbit, clock, and Earth-rotation products in public archives, organized into one directory per GPS week. Brahe's IGSProductsClient lists the products in those directories, downloads and caches them, and returns orbit files as parsed SP3 objects that chain into per-satellite trajectories with SP3Satellite.from_files. See SP3 Precise Orbit Files for the file format and the trajectory types. The client uses the same caching, retry, and BRAHE_NETWORK_MODE behavior as the other ephemeris clients.

Sources¶

A client reads from one archive, given to the constructor as an IGSProductSource or, in Python, its name ("CDDIS", "GARNER", or "BKG").

Source Default base URL Holdings
CDDIS https://cddis.nasa.gov/archive/gnss/products/ The full archive from all analysis centers. Requires a NASA Earthdata login.
Garner http://garner.ucsd.edu/pub/products/ The Scripps Institution of Oceanography mirror. The full archive from GPS week 576, from all analysis centers. No login.
BKG https://igs.bkg.bund.de/root_ftp/IGS/products/ The Federal Agency for Cartography and Geodesy. GPS week 2238 and later only, and only the IGS combination and CAS products. No login.

Garner is served over plain HTTP. Its HTTPS certificate chain ends at a root authority (emSign Root TLS CA - G1) that is not in the Mozilla and certifi trust bundles, so verification fails, and the client therefore does not use HTTPS for it. Files downloaded from Garner are not protected in transit. BKG and CDDIS use HTTPS. A product that is missing on the chosen source is an error; the client never falls back to another source.

CDDIS Credentials¶

CDDIS requires a NASA Earthdata login. Accounts are free and are created at urs.earthdata.nasa.gov/users/new; the CDDIS archive access page describes the login. IGSProductsClient("CDDIS", cddis_username=..., cddis_password=...) in Python and IGSProductsClient::with_cddis_credentials in Rust build a CDDIS client with credentials. The client reads no environment variables, and a CDDIS client built without credentials fails at the login.

CDDIS redirects each request to the Earthdata login service. The client follows that redirect itself and sends the credentials, as HTTP Basic authentication, only to urs.earthdata.nasa.gov; the file host never receives them. The session cookie that CDDIS sets after login is kept for the redirects that follow.

Listing Products¶

list_products(epoch, ...) lists the GPS week directory that contains epoch, and list_products_between(start, end, ...) lists every product whose coverage overlaps [start, end]. Each result is an IGSProduct holding the parsed IGSProductFileName, the published name, the URL, the size in bytes when the listing provides it (the Apache listings of Garner and BKG do not), and the GPS week of the directory it was listed in. list_files(epoch) returns the raw names of the directory, including files that are not products, and list_weeks() returns the week directories of the archive.

Both typed listings accept the filters center, solution, content, and format. They take an IGSAnalysisCenter, IGSSolutionType, IGSContentType, and IGSFileFormat, or in Python their string codes ("COD", "FIN", "ORB", "SP3"). A code outside the listed variants is kept as an Other value and matches only products published with that code. Names that match neither file name convention are left out of typed listings.

Two conventions name the files. Long names, used from GPS week 2238, look like IGS0OPSFIN_20243150000_01D_15M_ORB.SP3.gz and encode the center, version, campaign, solution, start epoch, span, sampling, content, format, and compression. Short names, used before week 2238, look like igs21000.sp3.Z and encode the center, GPS week, day of week, and an optional ultra-rapid hour, with the content and format taken from the extension. The center and solution of a short name come from a three-letter code: igr is the IGS rapid product, igu the IGS ultra-rapid product, and unlisted codes are final products. IGSProductFileName.parse decodes either form.

An ultra-rapid product covers 48 hours: 24 hours fitted to observations and 24 hours predicted. A short-name ultra-rapid file is filed under the week of its named time, but its coverage begins 24 hours before that time. For this reason list_products_between lists, besides the weeks containing start through end, the weeks that can hold products filed up to one day after end or beginning up to three days before start. Such an extra week that does not exist on the source is skipped.

Listings are cached under $BRAHE_CACHE/igs/listings/ for one hour by default, so a product published during the day appears on the next listing. The cache_max_age argument sets that age in seconds.

use brahe as bh;
use bh::igs::{
    IGSAnalysisCenter, IGSContentType, IGSFileFormat, IGSProductFilter, IGSProductSource,
    IGSProductsClient, IGSSolutionType,
};
use bh::time::{Epoch, TimeSystem};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = IGSProductsClient::new(IGSProductSource::Garner);
    println!("Source: {}, base URL: {}", client.source(), client.base_url());

    // Any epoch inside the week selects it; this one falls in GPS week 2340
    let epoch = Epoch::from_datetime(2024, 11, 12, 12, 0, 0.0, 0.0, TimeSystem::GPS);
    println!("Files published for the week: {}", client.list_files(epoch)?.len());

    // Final orbit products in SP3 format from the CODE and IGS analysis centers
    for center in [IGSAnalysisCenter::COD, IGSAnalysisCenter::IGS] {
        let filter = IGSProductFilter::new()
            .with_center(center.clone())
            .with_solution(IGSSolutionType::Final)
            .with_content(IGSContentType::Orbit)
            .with_format(IGSFileFormat::SP3);
        let products = client.list_products(epoch, &filter)?;
        println!("\n{} final SP3 orbits: {}", center.code(), products.len());
        for product in products.iter().take(3) {
            let name = &product.file_name;
            println!(
                "  {}: starts {}, span {:.0} h, sampling {:.0} s",
                product.name,
                name.start_epoch(),
                name.span().unwrap() / 3600.0,
                name.sampling().unwrap()
            );
        }
    }

    Ok(())
}

Downloading Products¶

download(product) fetches a product into the cache and returns the cached path of the file as published. Published products do not change, so a cached file is returned without a request. The cache path is $BRAHE_CACHE/igs/<source>/<week>/<published name>, and get_igs_cache_dir() returns the igs directory.

save(product, destination, keep_cached=False, decompress=False) downloads a product and writes it outside the cache. An existing directory, or a path whose last component has no extension, is treated as a directory and the published name is kept, while a path with an extension is the file written; a missing directory is created. The file is written as published, and SP3.from_file reads gzip and Unix-compressed (.Z) files directly. With decompress true a gzip or .Z product is written decompressed, and in a directory it loses the .gz or .Z suffix. A destination inside the cache is an error, checked before anything is downloaded. With keep_cached false the cached copy is removed, so a later download fetches the file again, and with keep_cached true the cache keeps it. To download or save every product in a range, loop over the result of list_products_between, as the range example below does.

download_sp3(product) downloads an SP3 product and returns the parsed SP3. Gzip and Unix-compressed (.Z) products, the latter common before GPS week 2238, are decompressed for parsing. It raises an error for a product that is not an SP3 file.

Downloading a Range of Orbit Files¶

download_sp3_range(start, end, center, solution, ...) returns the daily orbit files of one center and solution that cover [start, end] as a list of SP3 objects in time order, ready for SP3Satellite.from_files. With pad=True, the default, it adds the day before start and the day after end, so that velocities derived for the samples at the ends of the range come from centered fits. A padding file that is missing from the listing or whose download answers 404 is skipped, while a missing file inside the range is an error that names the day and the source. Any other download or parse failure, for a padding file or a file inside the range, is an error. For long names the client selects the daily 01D orbit file; when a center publishes several samplings, for example COD at 5 and 15 minutes, it chooses the coarsest unless sampling gives an interval in seconds. For short names it selects cccwwwwd.sp3, and sampling does not apply because those names do not encode one. A range that crosses GPS week 2238 returns short-name and long-name files together, and chaining them works.

The files are downloaded and parsed on up to concurrency threads, 4 by default, set with the concurrency argument in Python and IGSRangeOptions::with_concurrency in Rust. The threads share the client's rate limiter, and a value of 1 downloads the files one after another. Once a file fails, no further file is started, and the error is that of the earliest file that failed. CDDIS requests run one at a time until one has succeeded, so that the threads share one Earthdata session.

use brahe as bh;
use bh::datafiles::sp3::SP3Satellite;
use bh::igs::{
    IGSAnalysisCenter, IGSContentType, IGSFileFormat, IGSProductFilter, IGSProductSource,
    IGSProductsClient, IGSRangeOptions, IGSSolutionType,
};
use bh::time::{Epoch, TimeSystem};
use bh::traits::DOrbitStateProvider;
use bh::utils::Identifiable;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    bh::initialize_eop()?;

    let client = IGSProductsClient::new(IGSProductSource::Garner);
    let start = Epoch::from_datetime(2024, 11, 11, 0, 0, 0.0, 0.0, TimeSystem::GPS);
    let end = Epoch::from_datetime(2024, 11, 12, 0, 0, 0.0, 0.0, TimeSystem::GPS);

    // Daily CODE final orbit files covering the range, plus one day on each side
    let files = client.download_sp3_range(
        start,
        end,
        IGSAnalysisCenter::COD,
        IGSSolutionType::Final,
        &IGSRangeOptions::default(),
    )?;
    println!("Downloaded {} daily SP3 files", files.len());
    for sp3 in &files {
        println!(
            "  {} to {}: {} epochs",
            sp3.start_epoch().unwrap(),
            sp3.end_epoch().unwrap(),
            sp3.num_epochs()
        );
    }

    // One continuous trajectory per satellite across all files
    let satellites = SP3Satellite::from_files(&files)?;
    let g05 = satellites
        .iter()
        .find(|s| s.get_name().as_deref() == Some("G05"))
        .unwrap();
    println!(
        "\nG05: {} samples from {} to {}",
        g05.len(),
        g05.start_epoch(),
        g05.end_epoch()
    );

    for hours in [0.0, 6.0, 12.0, 18.0] {
        let epoch = start + hours * 3600.0;
        let state = g05.state_eci(epoch)?;
        println!(
            "{}: r = [{:.1}, {:.1}, {:.1}] m, |v| = {:.1} m/s",
            epoch,
            state[0],
            state[1],
            state[2],
            state.fixed_rows::<3>(3).norm()
        );
    }

    // Save the files covering the range, decompressed, to a directory of choice
    let directory = std::env::temp_dir().join("brahe_igs_download_range");
    let filter = IGSProductFilter::new()
        .with_center(IGSAnalysisCenter::COD)
        .with_solution(IGSSolutionType::Final)
        .with_content(IGSContentType::Orbit)
        .with_format(IGSFileFormat::SP3);
    let mut paths = Vec::new();
    for product in client.list_products_between(start, end, &filter)? {
        paths.push(client.save(&product, &directory, false, false)?);
    }
    println!("\nSaved {} files:", paths.len());
    for path in &paths {
        println!("  {}", path.file_name().unwrap().to_string_lossy());
    }
    std::fs::remove_dir_all(&directory)?;

    Ok(())
}

Ultra-rapid ranges are rejected

IGS issues an ultra-rapid orbit file every six hours, and each covers 48 hours. Consecutive issues therefore describe the same times with different values: the 00:00 issue predicts noon, and the 06:00 issue fits noon from observations. Chaining them would overlap, and choosing which issue supplies each time is a policy decision that depends on the application. download_sp3_range raises an error for the ultra-rapid solution before it makes any request. To use ultra-rapid orbits, list the products, choose the issues, and download them with download_sp3.

Rate Limits, Retries, and Timeouts¶

The client limits itself to 60 requests per minute and 3600 per hour, counting each attempt to fetch a listing or a file. A request over a cap waits until the cap allows it. The rate_limit argument takes a RateLimitConfig with other caps, and RateLimitConfig.disabled() removes them. Files and fresh listings served from the cache make no request and do not count.

A request that fails with HTTP 429, 500, 502, 503, or 504, or with a connection failure, is retried up to max_retries times, 3 by default. Each retry waits for an exponential backoff with jitter, drawn from a window that starts at 0.5 s and doubles up to 30 s, or for the time in the server's Retry-After header when that is longer, also up to 30 s. A connection must open within 30 s, and the response must start, and each read of its body must return, within 60 s. Every request sends the User-Agent brahe/<version>.

Offline and Network Mode¶

BRAHE_NETWORK_MODE=offline serves cached listings of any age and cached files, and an uncached listing or file is an error that names the mode. offline-strict serves a cached listing only while it is younger than cache_max_age. Offline, the weeks that list_products_between adds around a range are taken from the cache when present and skipped when not, so an offline listing can omit products filed in an uncached neighboring week; the weeks that contain part of the range must be cached. Cached product files are served in every mode because they do not expire. A failed request is retried up to max_retries times for transient errors, and in online mode a failure is an error rather than a fall back to an older cached listing. See Environment Variables.
